# Isolated ProAV AirPlay handoff experiment

This branch is a temporary macOS harness, not a production fix. Do not merge it into the integration or example branches. The completed native-codec source remains immutable at `566c70d00c2fea7a14af81d404f82c231278aab4`; its logs remain outside the repository at `~/Library/Application Support/LumenAirPlayExperiment/20261015/`.

## What is implemented

One actual `ProAVPlayer` uses its existing `KSAVPlayer` / AVQueuePlayer view, local server, `MEPlayerItem`, remux sessions, APAC converter and FLAC converter. Its temporary SPI initializer skips the normal global workspace purge; the harness cleans up only its own workspace. Experiment SPI opts in before preparation. All normal players leave it off and retain their existing initialization. The disabled diagnostic path performs no file reads, demuxing, payload hashing or packet retention and does not change mux input or output. The HLS server remains bound to `127.0.0.1`.

The initial launch is real FLAC HLS at a requested nonzero source position (12 seconds), using an explicitly selected eligible audio stream. No media is opened until **Prepare FLAC baseline**. No automatic play, route change or codec handoff occurs. The player starts muted. The native A/B/C controls are absent; their evidence is reused, not repeated.

**Mark TV selected** and **Mark local selected** record an observed picker selection; they do not select a route and must not substitute for inspecting the picker. **Confirm receiver FLAC progression** requires an operator-confirmed receiver picture plus a ready FLAC item progressing externally for at least two seconds. All codec-change preparation is gated on that precondition. A fetch/routing failure blocks the experiment; it does not authorize LAN serving or a different network configuration.

**Prepare APAC / Prepare FLAC** starts one counterpart through the existing `makeLaunch` and real remux/conversion path, using fresh options and the same selected audio stream. Its normal session readiness requires the existing video segment count and, for APAC, an audio fragment. The 30-second experiment deadline does not change the existing queued-source-switch ten-second timeout. Actual library refusal/failure blocks the case instead of masquerading as APAC success.

**Commit direct** performs a non-nil replacement on the existing AVQueuePlayer. The existing asset factory, resource-loader ownership, options and item observers are maintained. Session-ready is not AVPlayerItem-ready: the transaction waits for actual item readiness, playable video, an available seek range, explicit timeline evidence and successful exact seek before success. The player is paused through that validation and resumes only if the previous item was playing. A failed transaction directly restores the retained old item and blocks further cases.

Automatic route-triggered rebuild is held only for this explicitly enabled experiment; raw KVO remains active through preparation and handoff. Logs record whether production policy would request a rebuild. Route checkpoints are nonblocking. Retain old producers through readiness and seek; stop a retired producer after a successful handoff, retaining its session, files, item, asset and loader until **Stop**. A cancelled candidate's producer stops but its files remain until Stop. There is at most one active and one pending producer, with no automatic retry.

## Timestamp evidence and refusal rules

`MEPlayerItem` opts into a first-successful-video-mux diagnostic only for these sessions. It records source stream identity, codec, PTS and DTS separately, explicit source/mux timebases, source start and a SHA-256 of the actual mux-input compressed payload. It retains the digest and scalar timestamps, not packet bytes. Nothing is rewritten.

At authorized runtime only, a detached diagnostic reads the existing generated init plus completed first fragment through FFmpeg's local `concat,file` demux path. It requires exactly one matching compressed video payload, rather than assuming the first demuxed packet corresponds to the first input packet across reordering. A missing or duplicate match, mux payload rewrite, non-EOF/bounded probe, unknown presentation time or inconsistent PTS/DTS shift rejects the case. Missing decode timestamps remain explicitly `Int64.min`; no inferred DTS is passed off as observed. Actual fragment stream/track IDs, timestamps and timebases are logged. FLAC is verified from the muxed audio codec; APAC is verified from the separate audio sample entry and its first fragment timestamps.

The source-to-fragment offset comes from that exact payload correspondence. The harness additionally requires AVFoundation's video track segments to expose an explicit identity source-to-track time mapping. Absent, empty, shifted or scaled evidence is a blocker, not permission to guess how the player normalizes HLS time. This deliberately conservative guard may stop on an HLS implementation that does not expose sufficient mapping metadata.

At commit, the active measured offset plus current item time gives the source position. Subtract the candidate's measured offset to obtain its seek target. Do not reuse the old raw item time or the requested launch offset. Logs preserve the requested and measured offsets, seek ranges, target, completion and observed time. The target must be nonnegative, available and reached within 1 ms with zero requested seek tolerance; the route is rechecked before resumption. Do not clamp it, retime media or weaken readiness to make the handoff pass. The APAC encoder's internal priming is not independently measured by this harness; its actual first output fragment PTS/DTS are recorded. This is a route/timeline experiment, not an A/V-sync or Atmos-quality certification.

## Private configuration and media

The app reads `LUMEN_EXPERIMENT_CONFIG`, a path to a private JSON file with `mediaURL` (a local file URL) and `audioTrackID` (an integer). Use the existing `atmos-pairs/natures-fury.TrueHD.Atmos.mkv` fixture outside the repository, stream 1, after the runtime stream check agrees. Its stored probe reports 111.177 s, H.264 High, one 48 kHz TrueHD Atmos audio track, source start zero. No source URL, credential, media or generated HLS is uploaded, published or copied in advance. Source and output stream selection are checked again when opening.

`LUMEN_EXPERIMENT_LOG` selects the private JSONL event path. Events contain ordered sequence/monotonic time, item identity, raw external-video KVO, status, rate, time control, codec and timeline evidence, errors by domain/code, manual route marks and cleanup state. They omit the media URL, file path and localized error text. Record sender/receiver OS and model separately at runtime.

## Focused runtime protocol after a fresh device grant

1. Check Mac use and the normal TV ownership lock, acquire only a free lock, and capture original route/volume/settings. Use the same macOS sender; no iPhone or other platform target. Prepare and play the FLAC baseline, select Apple TV with the existing picker, mark that observed selection, and verify actual receiver picture plus externally advancing HLS. Confirm the preflight in the harness. Stop on a loopback fetch/routing error or ambiguous timeline metadata.
2. With FLAC remote, prepare APAC. Deliberately select local during preparation, mark the selection, then commit after the ready checkpoint and the local route agree. Observe raw KVO, item identity, actual readiness/seek, source/item time continuity and local APAC progression. A false video flag alone never identifies a route.
3. Prepare FLAC while local APAC continues. At the ready checkpoint select Apple TV, mark the selection and directly commit FLAC. Verify external progression and whether direct replacement produces a teardown-like false transition.
4. One reconnect variant: while a new APAC candidate prepares from remote FLAC, select local, then reselect Apple TV before commit. Cancel the obsolete APAC candidate, prepare FLAC at the current source position and commit FLAC. Do not send APAC to the external receiver to finish a checkpoint.

Keep cases short and sequential with the existing 30-second preparation/direct-transaction bounds and no repeated retries, listening or endurance phase. Native A/C are not repeated; B's two remote and one local ten-second readiness timeouts remain a separate limitation, not an AirPlay-only diagnosis. The completed native direct-replacement observation is evidence for one native same-codec macOS case only. Neither it nor this unrun harness closes the original production finding. macOS has no activator in the existing ProAV path; no Atmos output or iOS/tvOS sender claim is made.

End by selecting the original local route, pressing Stop and **Inspect cleanup**, closing the app, verifying its processes and owned workspace/server are gone, restoring changed settings and temporary launch environment, deleting private configuration and releasing only the owned TV lock. Preserve raw evidence outside the repository. This preparation acquires no lock and starts no playback.
